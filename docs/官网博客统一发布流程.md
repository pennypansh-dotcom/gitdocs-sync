# GitDocs Sync 官网博客统一发布流程

官网使用 GitHub 的 `gh-pages` 分支发布。自动流程已经配置完成，不需要再修改 `Settings → Pages`，也不需要手工运行构建命令。

## 每次发布新文章

1. 复制 `docs/blog-article-template.md`。
2. 填写标题、摘要、日期、slug、分类和正文。
3. 准备发布时，删除 `draft: true` 或改成 `draft: false`。
4. 在 GitHub 打开 `site/blog/posts/` 文件夹。
5. 点击 `Add file` → `Upload files`。
6. 上传 Markdown，提交到 `main` 分支。
7. 打开仓库的 `Actions` 页面，等待 `Publish website and blog` 变成绿色。
8. 系统随后自动触发 `pages build and deployment`；它也变成绿色后，文章正式上线。
9. 打开 `https://pawsitivetime.com/blog/` 检查标题、正文、表格和链接。

系统会自动完成文章 HTML、Blog 列表、SEO/GEO 信息、外链属性、RSS、sitemap 和正式发布。

## 修改文章

在 GitHub 中打开 `site/blog/posts/` 下的原 Markdown，点击铅笔图标修改并提交。只要 `slug` 不变，正式网址就不变。

## 暂时不发布

在文章头部保留：

```yaml
draft: true
```

草稿不会进入 Blog 列表和 sitemap。

## 使用其他写作工具

Typora、Obsidian、AI 写作工具或其他 Markdown 编辑器都可以使用。最终只需把符合模板的 Markdown 上传到 `site/blog/posts/`。

建议发布顺序：

1. 先发布官网原文。
2. 确认正式网址可以打开。
3. 再发布到 Dev.to，并将 canonical URL 设置为官网文章地址。
4. LinkedIn 发布摘要或改写版，链接回官网全文。

## 发布失败

先打开 GitHub `Actions`：

- `Publish website and blog` 失败：通常是文章缺少标题、摘要、日期、slug、作者或语言。
- `pages build and deployment` 失败：通常是 GitHub Pages 发布问题，可以重新运行该任务。
- 两项都成功但页面暂时没变化：等待一到三分钟后刷新正式网址。

不要重复上传同一篇文章。修正原 Markdown 并重新提交即可。
